## Problem
Nocna kopia 24.10 02:30 OK (id 47, 96/96), ale 3 decyzje „Kopia zapasowa nieudana” (NEW) z 23.10 (04:44, 07:00, 12:30 UTC) zostają otwarte — Administrator HHL widzi alarm mimo działającej kopii.

## Do zrobienia
1. Przy pierwszym przebiegu OK po błędzie zamykać automatycznie decyzje „Kopia zapasowa nieudana” (rozstrzygnięcie systemowe z id przebiegu) — także ryzyko `JOB_FAILURE` backup-stale.
2. Te 3 zamknąć cicho (migracja), bez powiadomień.
3. Test w `tests/db/backup.sh`: ERROR → decyzja NEW; następny OK → decyzja RESOLVED.
4. Drobne: `backup_runs.files = 0` przy istniejących częściach — licznik plików.

## Odbiór
