## Zakres (baza i logika)
1. `import_schedule` (i każda ścieżka importu pliku KSH, w tym przyszła synchronizacja SharePoint) przyjmuje `p_quiet boolean default false`. Parametr działa tylko dla HHL_ADMIN — dla innych ról błąd albo ignorowanie (opisz w PR).
2. Przy `p_quiet = true` cały import w trybie `tower.bulk_quiet`:
   - 0 powiadomień w żadnym kanale (IN_APP, EMAIL, WEB_PUSH, SMS — także `trg_sms_load_changes` i `trg_plan_dates_notify`);
   - 0 decyzji / ryzyk wynikających z samej zmiany danych (data, okno, godzina); ryzyka stanu (np. brak dokumentu) jak zwykle przy następnym przebiegu;
   - `audit_log` z oznaczeniem „import bez powiadomień” (kto i kiedy).
3. Test bramy: import z `p_quiet` → 0 nowych `notifications`, 0 `decisions`, 0 `sms_outbox` z importu; bez `p_quiet` jak dziś.
4. Front (koordynator): w oknie importu KSH, tylko HHL_ADMIN — „Importuj bez powiadomień…” + ostrzeżenie; przekazuje `p_quiet`.
